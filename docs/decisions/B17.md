# B17: calendars (Google), ICS invites and feeds, calls

## Summary

Records with a time can reach people's calendars, and calls can be logged on records.

- **Schedulable trait.** An entity declares which of its fields are the title, start and end
  (and optionally the place and a description), and whose calendars it belongs on
  (`traits: { schedulable: { … } }`). Everything below works for any entity that carries it.
- **Google Calendar** (`@hykr/connectors/google-calendar`, transport only, plus the server's
  `calendar` feature). Each person connects their own Google account by OAuth (PKCE, offline
  access). Their schedulable records then appear in their primary calendar, read as they may see
  them (hidden fields never leave), and follow every change. Google tells us about changes made
  there through a watch channel that posts to the B10 inbound webhook; a change to one of our
  events is stored as a `calendar.event_moved` or `calendar.event_removed` event that the
  application may act on. Busy times from Google answer "when am I free?".
- **ICS.** A record's invite goes by email with an RFC 5545 `.ics` (METHOD:REQUEST); later changes
  send an update (SEQUENCE + 1) and a deletion sends a CANCEL. Each person can also make a private
  ICS feed URL (an unguessable token, stored hashed, revocable) that any calendar app subscribes to.
- **Calls.** A `TelephonyProvider` interface (no provider ships) and a call log on records:
  calls logged by hand or by the assistant, a click-to-call command that asks the business's
  provider to connect the call, and an op a provider's inbound webhook handler uses to record its
  status.

| 10 | Sync is one way, records to Google. The subscriber `calendar.records` takes every stored event about a schedulable entity and queues `calendar.sync` for the record. The job works out whose calendars it belongs on (the trait's `people` columns, default the owner), adds the people who already have it, and for each with an active connection reads the record **as that person** (scoped repository, `toRead`): reachable and not `hiddenWhen` → upsert; otherwise → delete. So another business's record never reaches a calendar, a field hidden from the person never reaches Google, and someone who loses access loses the event. | Plan ("sync events from schedulable entities"); CLAUDE.md read rule. |
| 11 | Event ids are deterministic (`bc` + a hash of business, entity and record, Google's base32hex alphabet), so an upsert is idempotent: update first (which also restores an event Google keeps as cancelled), insert on 404. The event carries `extendedProperties.private` naming the business, entity and record. | Default (Google keeps deleted ids). |
| 12 | Changes made in Google to our events are not written back by the framework. ## Assumptions to review

- **Google only.** Microsoft 365 (Outlook) is not built; the connector shape (OAuth, upsert,
  changes, free/busy) is what a second provider would implement. Is Outlook needed for the first
  version (PRD Win 7.1 names "Google/Outlook")?
- **One way.** Records go to Google; changes made in Google are reported as events and the
  application decides (the sample moves the meeting). Should the framework instead overwrite
  Google with the record, or always accept the calendar's time?
- **Whose calendars.** The trait's `people` columns (default the owner). Should every member who
  can read a record get it, or should participants (B7) be invited automatically?
- **Primary calendar.** Events go to the person's primary calendar. Should a person pick a
  calendar, or should the framework make a dedicated one?
- **Invite replies.** Attendees' accept/decline replies are not read (no inbound mail); RSVP is
  off. Is tracking replies needed?
- **Automatic invite updates.** A change to an invited record emails every recipient an update.
  Should a person confirm updates to external recipients first (they are sends to others)?
- **Feed scope and window.** A feed shows the person's own records, 90 days back to a year ahead.
  Should a manager have a team feed?
- **Who reads others' availability.** `calendar.availability.read` (owner, admin, ops). Only busy
  times, never titles. Right?
- **Calls about no record.** Visible to who logged them, the member on them and
  `calls.read_all`. Right?
- **Recordings.** Not stored. Needed, with consent and retention (B18)?

## API sketch

```ts
// @hykr/contracts: the trait
traits: {
  schedulable: {
    title: 'title', startsAt: 'startsAt', endsAt: 'endsAt',   // read-schema fields
    location?: 'address',                                      // text or Address
    description?: 'notes',
    people?: ['ownerId', 'assigneeIds'],                      // columns of user ids (default: owner)
    hiddenWhen?: { field: 'status', in: ['cancelled'] },
  },
}
freeSlots(busy, { from, to, minutes, stepMinutes?, hours?: { from: '09:00', to: '18:00' }, timeZone? })

// @hykr/connectors
icsCalendar({ method?, prodId, name?, events: IcsEvent[] }): string
interface TelephonyProvider { name; label; connector?; dial(req: DialRequest, ctx: { credentials?: unknown }): Promise<DialResult> }
// @hykr/connectors/google-calendar
googleOAuth / googleCalendarClient(transport, accessToken) / googleCalendarConnector / createFakeGoogle() / fakeGoogle()

// HTTP (people; the assistant only where noted)
GET    /api/calendar/providers                         → [{ name: 'google', available }]
POST   /api/calendar/connections { provider }          → { url }
GET    /api/calendar/google/callback?code&state        (anonymous; redirects to CALENDAR_RETURN_URL)
GET    /api/calendar/connections                       → mine
DELETE /api/calendar/connections/:id
GET    /api/calendar/busy?from&to&userId               (assistant too)
GET    /api/calendar/free?from&to&minutes&step&hours&userId   (assistant too: find-free-time)
POST   /api/calendar/invites { entity, id, to: [{ email, name? } | { userId }], lang? }   (assistant: parks)
GET    /api/calendar/invites?entity&id
POST   /api/calendar/feeds { label? }                  → { feed, url } (url once)
GET    /api/calendar/feeds
DELETE /api/calendar/feeds/:id
GET    /api/calendar/feed/:token                        (anonymous, text/calendar)
POST   /webhooks/google-calendar/:connection           (B10 inbound)

POST   /api/calls { direction, status, from?, to?, entity?, id?, startedAt?, endedAt?, durationS?, notes? }
POST   /api/calls/dial { to, from?, entity?, id? }     (assistant: parks)
PATCH  /api/calls/:id { notes?, status?, endedAt?, durationS? }
GET    /api/calls?entity&id | GET /api/calls | GET /api/calls/:id

// server
contributes: { telephonyProviders: [...] }
callProviderUpdate(): WriteOp            // for a connector handler: ctx.write(callProviderUpdate(), { provider, externalId, status, … })
memberPrincipal(ctx, { userId, tenantId }) // a member, for a subscriber that writes as them
```

## Test plan

- Unit (`framework/connectors`): ICS escaping, folding at 75 octets, UTC times, CANCEL; OAuth URL
  with PKCE, code exchange and refresh against the fake; the client's upsert (update, then insert
  on 404; a cancelled event restored), changes with a sync token and 410; free/busy; the connector's
  verify (token, constant time, missing headers) and parse; the fake's bookkeeping.
- Unit (`framework/contracts`): `freeSlots` (busy overlaps, steps, working hours in a time zone).
- E2E (`framework/api/test/framework/calendar.e2e.test.ts`, fixture `appointments`):
  - connect: the URL carries PKCE and a sealed state; the callback stores sealed tokens (no
    token in the database in the clear, none in the audit), redirects; a tampered or expired
    state is 400; the assistant cannot start one; disconnect removes our events and revokes;
    another person's or business's connection is 404;
  - sync: create, update, delete reach Google; a staff member's own appointment reaches their
    calendar without the field hidden from staff; another business's records never reach it; a
    record nobody may read any more is deleted; an unchanged update sends nothing;
  - watch: a notification with the right token is stored once and pulls changes; a moved event
    stores `calendar.event_moved`; a deleted one `calendar.event_removed`; a wrong token is 401,
    an unknown connection 404;
  - availability: busy and free slots; another member's needs the capability;
  - invites: an invite reaches Mailpit with a REQUEST `.ics`; the assistant's invite parks and is
    audited; moving the record sends SEQUENCE 1; deleting sends CANCEL; another business's record
    is 404; the hidden field is not in the `.ics`;
  - feed: lists the person's records, hidden fields out; another business's not; revoked is 404;
  - calls: log on a record (reader 404 without access to the record, another business 404), dial
    without a provider is refused, with the fixture's provider it dials and a provider webhook
    completes it as the system principal.
- Sample (`application/api/test/domain/calendar.e2e.test.ts`): a meeting reaches the owner's fake
  Google calendar; moving it in Google reschedules the meeting.

## Deferred

- Microsoft 365 / Outlook and CalDAV providers.
- Reading invite replies (iMIP REPLY) and showing attendees' answers.
- Picking a calendar other than the primary one.
- A team or business-wide feed.
- Call recordings, transcripts and their retention (B18); a provider's number masking rules.
- Writing changes made in Google back into records by default (the application decides today).
