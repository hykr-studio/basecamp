# B23: share links that last and are sent

## Summary

Interioring asked for share links that last as long as the work they serve, and for links the
framework sends itself. An interior job runs 3 to 9 months, plus a year of warranty. A studio's
website form is pasted once and lives for years. B9 made every link end (at most 90 days), and
nothing but a person copying a link could deliver one. This unit keeps B9's rules (only a token's
hash is kept for a link; a link names one target and one recipient) and adds:

- **Links without an end.** `expiresInDays: null` makes a link with no end date (`expires_at` is
  null). It is allowed only where the application's declaration says `lasting: true`
  (`defineShareable`, `definePublicForm`) **and** the business allows it (`shares.allowLasting`,
  off by default). Anything else is refused `too_long`. Revoking it ends it at once, as before.
- **Renew.** `POST /api/shares/:id/renew { expiresInDays | null }` (`share.renew`) moves the end
  date under the same rules. The token stays the same, so the address the recipient holds keeps
  working. An ended link comes back; a revoked one does not (`link_revoked`).
- **Reissue.** `POST /api/shares/:id/reissue { send? }` (`share.reissue`) revokes the link and
  makes a new one with the same settings, under a new token.
- **Sending.** `POST /api/shares { …, send: { channel? } }` makes the link and queues its send in
  one write. The worker sends it to the link's own recipient. On WhatsApp it uses the
  declaration's approved template, with the token in its URL button, or else a plain message inside
  the 24-hour window. Otherwise it sends an email. `app.share_sends` keeps each send's state.
- **The assistant.** `create-share-link` and `send-share-link` draft a link and its send (or a
  reissue that sends). They wait for the person's approval. The assistant never sees the token or
  the address.
- **The business's domain.** A link's URL, and the address an email or a plain WhatsApp message
  carries, use the business's first verified domain (A11) when it has one.
- **Abuse limits for lasting forms.** A form link with no end takes 20 answers an hour from the
  link and 5 from one address (`PublicFormDef.rateLimit`). Over that it answers 429
  `too_many_answers`. It also refuses an answer whose trap field (`hp`) is missing or filled
  (`spam_suspected`).

The sample: an order's page is lasting and goes out in `order_link_v1` (a URL button). The brief
form is lasting. The application's `app.sends` level rule covers the assistant's share drafts.

## Decisions

| # | Decision | Source |
|---|---|---|
| 1 | No end at all, rather than a long cap. It is allowed only where the declaration says `lasting` and the business's `shares.allowLasting` is on. `maxDays` keeps its range of 1 to 3650 for links that do end. A link made under support access still ends with that access (S1), even when it asks for none. | Open question 1 (the suggested answer). |
| 2 | `expires_at` is nullable. Every reader treats null as "never ended": `ShareGuard`, the `share` grant's SQL (`expires_at is null or expires_at > now()`), a form's use count, a session's end (`min` with no end is the session's hours) and every `expiresAt` that leaves the API (null). | Brief, "Database". |
| 3 | Renew is the maker's, or a `shares.manage` holder's, like revoke (anyone else: 404). People only. It is audited as `share.renew` with the before and after. It is refused on a revoked link (`link_revoked`). An ended link may be renewed: it opens again at the same address. | Brief, "Renew". |
| 4 | Reissue revokes the old link (`revoked_by` is the person) and makes a new one in the same write. The new link has the same kind, target, recipient, code channel and address, `maxUses`, uses and label. It lasts the same length (its days, rounded), or has no end, under today's rules (a business that turned `allowLasting` off gets `too_long`). The new token is answered once, as `share.create` answers it. | Brief, "The token"; B9 decision 6. |
| 5 | **The token waits sealed on the send**, never in clear. A send is asked for when the link is made, or reissued, because nothing else holds the token. `share_sends.token_sealed` holds the token sealed with `SECRETS_KEY` (`requireSecretBox`, AAD `share-send:<tenant>:<send id>`), and the send's `finish` wipes it, sent or failed. This keeps document.send's crash-safe path (the stored event `share.send_requested`, the `share.send` subscriber, the `share.send` queue). A job-only token (the brief's first idea) would be lost on a crash between commit and enqueue. A send that cannot open its token fails `token_unavailable`. | User's answer (sealed on the send row); open question 2. |
| 6 | No send of an existing link: no `POST /api/shares/:id/send`. A link made earlier is sent by reissuing it (`{ send: {} }`), which makes a new token. | User's answer; open question 2. |
| 7 | Who may ask for a send. The person making the link (its maker) may. On a reissue, the link's maker may, and anyone else needs `customers.message`. The assistant always waits for approval (`needsApproval('agent_sends_share')`), as `document.send` does. A link with no recipient cannot be sent: 400 `no_recipient`. A channel the declaration does not send by is refused `channel_unavailable`. | Brief, "Who may send". |
| 8 | A send goes to the link's own recipient only: its contact, its customer (that customer's contact, then the account's email), or its email. The order is the requested channel, else the declaration's `send.order`, else WhatsApp then email. WhatsApp needs a contact that is reachable, `consent('service')` and the business's number. It sends the declaration's template when approved (in the reader's language, else English), else a plain message inside the 24-hour window. Email uses the declaration's words, or the framework's. None of these works: failed `unreachable`. A link revoked or ended before its send: failed `link_revoked` / `link_expired`. | Brief, "Sender"; documents/sender.ts. |
| 9 | At most once, as B2's sender does. One statement claims the send (`claimed_by`). The channel, address and message are written before it finishes, so a try after that finishes it instead of sending again. A send found `sending` by the job that claimed it, or after the 5-minute lease, is finished from what is recorded: sent if a channel took it, else failed `interrupted`. | Brief, "Storage"; B2 decision 26. |
| 10 | A declaration's template is checked at start. It must be one of the application's templates, and it must have a URL button whose path is `/share/{{1}}`. The token is the button's parameter. It is never a body parameter, so `params(target, reader)` never sees it. | Brief, "Declaration". |
| 11 | **Nothing keeps the token or the URL.** Events (`share.send_requested`, `share.sent`, `share.send_failed`) carry ids and states. Audit rows carry the link's info and the send's recipient and channel. The assistant's answers carry what will happen. The message log keeps `[link]`: an `OutboundMessage` lists its `sensitive` text, and the outbound service scrubs the stored body once the message is sent or has failed (or at once, when the business's plan refuses it). The mailer's log keeps only the subject, scrubbed the same way. | Acceptance criterion; B9 decision 6. |
| 12 | The assistant's path is its own route, `POST /api/shares/drafts` (and `/drafts/reissue/:id`). It lifts `humans_only` for this path only. It always sends to a named recipient, and an assistant's draft always waits. The operation is `share.create` (or `share.reissue`) with `via: 'draft'`, which is not the framework's own operation, so the application's level rules apply to it (the sample's `app.sends`, level `external`). Plain `POST /api/shares` stays people-only, `system: true`. Both ops are registered for an approval's replay. An assistant drafts only for a person with an account (`people_only` otherwise): a link's maker is a member. | Brief, "The assistant". |
| 13 | What the assistant sees. A draft answers `{ id, status, send, message }`, where the message is "A link to inquiry "Mrs Rao" will be sent to Asha on WhatsApp". It never includes the token or the URL. The answer to any principal but a person leaves the token out, so the idempotency store, an approval's replay and Mastra's run keep none. The approval card reads "Send a link to <record> to <recipient> on <channel>". | Brief, "What the assistant never sees". |
| 14 | No captcha. A lasting form link has hourly Redis counters (20 per link, 5 per link and address; `rateLimit: false` for none), and a trap field (`hp`) that the page always sends empty and a bot fills. The counters are the form's own, so `THROTTLE=off` does not turn them off. They apply only to links with no end, so a form link that ends behaves as before. | Open question 3 (the suggested answer). |
| 15 | The business's domain. Its earliest verified origin (`verifiedOriginOf`) is used for the URL `POST /api/shares` and reissue answer, for an email's link, and for a plain WhatsApp message's link. A template's URL button keeps `APP_URL`: its base is fixed per template when it is synced, and one approved template serves every business. | Open question 4 (the suggested answer). |
| 16 | Longer sessions for gated links are not in this unit (the user's choice). `shares.sessionHours` stays as it was. | User's answer; open question 5 deferred. |
| 17 | The app. `<ShareLinks>` offers "No end date" where the kind is lasting and the business allows it, and "Send it to them" when the link has a recipient. Each link shows its latest send's state, with Renew and New link (or Send a new link) beside it. `useRenewShare`, `useReissueShare` and `useSendShare` are new hooks. The public form sends the trap field empty from a hidden input. | Brief, "App". |

## Answers to the open questions

| Question | Answer |
|---|---|
| Allow links with no end at all, or only a long cap? | No end, only where the declaration says `lasting` and the business allows it (decision 1). |
| Send a link made earlier, though its token is not stored? | No: send at creation, or reissue (decision 6). The token waits sealed on the send until it goes (decision 5). |
| A captcha for lasting public forms? | Not now: rate limits and a trap field (decision 14). |
| Use the business's domain in WhatsApp URL buttons? | No: the button keeps `APP_URL`. The domain is in the URL, emails and plain messages (decision 15). |
| Longer sessions for gated links? | Deferred (decision 16). |

## Assumptions to review

- **A reissue keeps the uses.** A form link reissued with `maxUses` keeps the answers it has
  counted, so it takes no more answers than the old link would have. Should a reissue start
  counting again?
- **The first verified domain.** A business with several verified domains has its links on the
  earliest verified one. Should a business pick one for links?
- **The limits are per link and address.** "5 per IP" counts one address on one link, not one
  address across all of a business's forms.

## Test plan

- `framework/api/test/framework/share-send.e2e.test.ts` (the share fixture: a lasting inquiry
  shareable that sends in `fixture_inquiry_link_v1`, a lasting website form and a busy one). It
  covers:
  - `too_long` without `allowLasting` or `lasting`;
  - a lasting link open 400 days on (a moved clock) while a 7-day one is 410, and revoked at once;
  - renew keeps the token, is audited twice, and refuses a revoked link;
  - reissue keeps the label and length, and the old link is 410;
  - a lasting form refuses a filled or missing trap field, the 6th answer from one address and the
    21st from the link;
  - a send on WhatsApp in the template, the token in the URL button, once, the sealed token wiped,
    and no token in audit, events, messages, approvals or idempotency;
  - by email on the verified domain;
  - a plain message in the window on the domain;
  - `no_recipient`, and a reissue that sends;
  - a send found `sending` fails `interrupted`, and two jobs at once send once;
  - the assistant's plain link refused, its draft parked, approved (made, sent, no token in the
    answer) and rejected (nothing made), and the scripted model.
- `framework/core/src/plugins/share.test.ts`: a form's default limits and their checks, and a send
  order's checks.
- `application/api/test/domain/share.e2e.test.ts`: an order's lasting page sent to its customer
  (`order_link_v1` on WhatsApp, its token not logged). The brief form's lasting link asks for the
  trap field.

## Deferred

- Remembered sessions longer than `shares.sessionHours` for gated links (decision 16).
- Several recipients on one link (B9 decision 7 stays).
- A captcha connector for lasting forms (decision 14).
- The business's domain in a template's URL button (decision 15).
- SSR, search indexing and link previews (B9 decision 25).
