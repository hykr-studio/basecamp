# V10: untrusted input, references and money, what the reviews left

## Summary

The reviews of V1 (untrusted keys and query strings), V2 (references) and V4 (money) approved
those units and left findings of the same classes. Each defect below was reproduced on the
compiled API by a test that failed first.

- **A NUL character (U+0000) in any text that reached Postgres was a 500** (22021 for text,
  22P05 for jsonb): every entity list, summary and write, feature routes (`/api/jobs?kind=`,
  `/api/calls`, `/api/comments/mentionable`, `/api/parties?q=`, `/api/documents`, the operator's
  `/api/platform/tenants?q=`), and Better Auth's `update-user`. With a genuine list cursor the same
  filter was blamed on the cursor (`bad_cursor`). Now one check at the request edge refuses a NUL
  anywhere a request sends text, with 400 `nul_character`.
- **Keyset cursors answered 500 when tampered with.** The inbox, comments and agent runs took any
  time JavaScript reads (`99999`, `-100000-…`) and any id (a NUL). They now read through one helper
  (`keysetOf`): a time Postgres stores, an id with no NUL and at most 128 characters, else 400
  `bad_cursor`. The SLA cursor refuses a NUL id too.
- **Three writes skipped the reference check.** `reviseWithChildren`'s `values` were inserted raw
  (another business's room, or one the writer cannot read: 200), a public form's answer was
  checked only in `run` (a guest's answer that would wait was `guest_cannot_wait` instead of the
  reference's 404), and undo put a deleted row back with a link its person could no longer read.
  Each now goes through `checkReferences`.
- **An order stored in a made-up currency could never be saved**, and the assistant's save on it
  parked for an approval that could only fail. `currencyOf` checks the stored currency in
  `authorize` too.
- **The server's currency check failed open without ICU data.** The server now refuses to start
  when Intl cannot list currencies.
- The rest are missing tests (the delivery log's `before`, a note's PATCH, a member of two
  businesses, the importer's own-key read), a guard scoped to its table, and corrections to V1.md,
  V2.md, V4.md, the developer guide and CLAUDE.md.

## Decisions

| # | Decision | Source |
|---|---|---|
| 1 | One mechanism for the NUL character, at the request edge, not route by route and not in an exception filter: a global Nest guard (`UntrustedTextGuard`, `framework/api/src/infra/untrusted-text.ts`, `APP_GUARD` in `app.module.ts`) walks `req.params`, `req.query` and `req.body` (keys and values, arrays and plain objects at any depth, with its own stack so a deep body cannot overflow it) and throws 400 `{ error: 'invalid', rule: 'nul_character', message, where }` naming the first place (`body.lines[2].title`, `query.q`, `path.id`). A guard runs after the body parser and before every pipe and handler, so no route can read the text first. | V1 review (both findings: "refuse `\u0000` in strings at the request edge"; "better, refuse NUL at the edge, so the class-22 backstop only ever sees cursor values"); task ("one mechanism for every route"). |
| 2 | Not an exception filter mapping 22021 to 400. A filter would answer after a query ran or a write half-happened elsewhere (a Redis key, a model call), would not see a NUL that reaches no Postgres text, and would leave the cursor backstop blaming a filter on the cursor. The edge refusal covers all of these and needs no SQLSTATE list (22021 and 22P05). | V1 review (the reviewer offered both); default: refuse input before it is used. |
| 3 | Better Auth's routes never reach a Nest guard (its handler is Express middleware) and their bodies are not parsed by the API. The same `nulAt` check runs in a Better Auth `hooks.before` (`createAuthMiddleware`, `infra/auth.ts`) on `ctx.body` and `ctx.query`, answering the same body through `APIError('BAD_REQUEST')`. Checked by test: before, a sign-up with a NUL in the name was 422 `FAILED_TO_CREATE_USER`, an email with one 400 `VALIDATION_ERROR`, and `POST /api/auth/update-user` with a NUL name a **500**. | Advisor; test. |
| 4 | `@TakesBytes()` marks a route whose body is a file's bytes (the local storage drivers' blob `PUT`): its body is skipped, its path and query are still checked. A JSON file uploaded there is parsed by the JSON body parser, and a NUL inside it is the file's data. No other route is exempt. | Default: only where the body is not text. |
| 5 | Text decoded later is checked by its reader: keyset cursors through `keysetOf`, the SLA cursor in `decodeSlaCursor`, entity list cursors through V1's class-22 backstop (`listQuery`), which now only ever sees a cursor's values. | Advisor; V1 review. |
| 6 | `keysetOf(at, id)` (`framework/api/src/features/inbox/cursor.ts`): the time through `storableInstant` (years 1 to 9999), the id a string with no NUL and at most 128 characters (ids are uuids, 36). `decodeKeyset` (inbox, comments) and the agent runs' `decodeCursor` use it. 400 `bad_cursor` for anything else. | V1 review ("read the cursor's date through storableInstant, or a shared helper that does the same, and refuse an id that holds a NUL or is longer than a set limit"). |
| 7 | `GET /api/agent-runs` used to ignore a cursor it could not read and answer the first page; it now answers 400 `bad_cursor`, as the inbox and comments always did. A client that sends back the page's `nextCursor` sees no change. | Default: one behaviour for every keyset cursor. |
| 8 | The importer reads a row's key with `ownValue(raw.values, o.key)`: a JSON or NDJSON row without a key column named `constructor` is `missing_key`, not keyed `function Object() { [native code] }`. | V1 review. |
| 9 | `reviseWithChildren` checks the references the application's `values` change, with `checkReferences(tx, p, spec, row, changed)` against the row it copies: a kept link passes (V2 decision 4), a changed one is loaded through the target's scoped repository. | V2 review ("call checkReferences on the application's values in revise()"); advisor (pass the source row). |
| 10 | `submitOp`'s load runs the create's own load (`base.load`) as the guest `run` writes as (`as(p, customer.id)`), after the use is spent and the customer found. A refused reference throws there, so the transaction rolls back: no use spent, no customer made, nothing asked. | V2 review ("call base.load inside submitOp's load"); advisor (same principal as `run`). |
| 11 | Undo putting a deleted row back checks the row's references as it was (`checkReferences(tx, p, spec, null, before)`), after the create rules and before the insert. A target the person can no longer read, or one deleted meanwhile, is the reference's 404 (`No such <target>`, with the field), and the row stays deleted. Undoing an update already got this from `repo.update`; the two now agree. This narrows V2 decision 4 ("an unchanged link was checked when it was made"): a restore is a create, made now, by this person. | V2 review; advisor. |
| 12 | `currencyOf` (`save-order.command.ts`) runs `knownCurrency` on the currency it returns, the stored order's included, so a save on an order stored in `ABC` is 403 `money_invalid` in `authorize` and never parks. Such an order still takes its transitions. V4 decision 5 and the guide's section 14 row said it "reads and changes as before"; both are corrected. | V4 review. |
| 13 | `canListCurrencies()` (`@hykr/i18n`) says whether Intl lists currencies (a function that answers a non-empty list); `assertConfig` refuses to start without it, for the API and the worker. `knownCurrency` stays lenient where there is no list (Hermes). An empty list now counts as "cannot list" (before, it made `XXX` the only currency). | V4 review ("refuse to start when Intl.supportedValuesOf is not a function or returns nothing"); advisor (unconditional, not only with `DEFAULT_CURRENCY`). |
| 14 | `meeting-references.sql` looks for each key on its own table (`conname = … AND conrelid = 'app.todos'::regclass`). A database that already ran the name-only guard has both keys on their tables, so the new guard skips there too (checked by `pnpm db:migrate` on `app_v10`). | V2 review (optional suggestion); task ("must stay idempotent"). |
| 15 | CLAUDE.md's money rule says a command that takes or writes a currency checks it in `authorize`, a stored record's own currency included. | V4 review. |

## Assumptions to review

- **A NUL is refused, never stripped.** A client that sends one gets a 400 and must fix its text.
  Stripping would change what was sent without saying so, and a key with a NUL has no safe
  stripped form.
- **Signed webhooks too.** An inbound webhook (WhatsApp, an integration's `/webhooks/…`, a job
  callback) whose JSON holds a NUL is refused 400, whole, before its signature is read. Checked
  by reading: each receiver stores its events synchronously, one insert per event into a jsonb
  column (`inbound_events.payload`, `integration_inbound.data`), outside one transaction. So
  before, the events of that delivery ahead of the one with the NUL were stored and the request
  then failed with a 500; now none of the delivery is stored. Either way the event with the NUL
  never is, and the sender retries until it gives up. Refusing the whole delivery keeps one
  mechanism and no 500; exempting the receivers (`@TakesBytes()`) would keep the partial store
  and the 500. A connector cannot strip the character today, since the guard runs before its
  `parse`. In guide section 14.
- **An unknown key in a body is checked too.** A NUL in a field the schema would have dropped is
  still a 400: the guard runs before the schema and does not know which keys a route reads.
- **Undo refuses rather than unlinks.** A deleted record whose target the person can no longer
  read stays deleted (404, the reference's answer), instead of coming back without the link.
  Coming back changed would not be the undo the person asked for.
- **A guest names no room.** The fixture's form asks for a room as text; a guest reads none of the
  business's records, so any id it sends is refused. An application that wants a guest to choose
  a record offers it as a choice and sets the id itself (`fixed`, or its own command).
- **The over-long id branch of `keysetOf` is defence in depth.** Over HTTP the cursor schemas
  (`max(200)`) refuse a cursor that long first, so the test asserts a 400, not `bad_cursor`.
- **No release notes exist** in the repository. The V2 repair (crossed meeting links nulled once)
  is recorded in V2.md's assumptions; whoever cuts the next release should mention it.

## API sketch

```ts
// framework/api/src/infra/untrusted-text.ts
nulAt({ lines: [{ title: 'a\u0000b' }] }, 'body'); // 'body.lines[0].title'
@TakesBytes() // on a controller or handler whose body is a file's bytes
```

| Route | Change |
|---|---|
| Every API route | A NUL in a route parameter, the query string or the body: 400 `{ error: 'invalid', rule: 'nul_character', message, where }` |
| `/api/auth/*` | The same, from Better Auth's before hook (`update-user` was a 500) |
| `GET /api/inbox`, `GET /api/comments`, `GET /api/agent-runs` | A cursor with a far-off time or a NUL id: 400 `bad_cursor` (was 500). One whose id is over 128 characters: 400 (the query schema's cap of 200 characters refuses it first). Agent runs: any cursor that is not a page's `nextCursor` is 400 (was ignored) |
| `GET /api/sla` | A cursor whose id holds a NUL: 400 `bad_cursor` |
| A command calling `reviseWithChildren` with `values` | A changed reference the writer may not name: 404 `{ error: 'not_found', message: 'No such <target>', field }` |
| `POST /api/share/:token/submit` | The same 404 before the answer is authorized; no use spent |
| `POST /api/undo/:id` | The same 404 when the restored row names a record the person cannot read |
| `POST /api/orders/save` (sample) | On an order stored in an unknown currency: 403 `money_invalid` in `authorize` (the assistant's no longer parks) |
| API and worker start | Refused when `Intl.supportedValuesOf` is missing, throws or lists nothing |

## Test plan

Each test below failed on the code before its fix, unless marked as a missing test.

- `framework/api/test/framework/untrusted-keys.e2e.test.ts`:
  - "a NUL character in what someone sends": ten GET paths (lists, summaries, `/api/jobs`,
    `/api/calls`, comments, a route parameter, a query key) and seven bodies (top level, nested,
    a key, a PATCH, custom values, a comment, wording) are 400 `nul_character`, and another
    business is unharmed. Failed first: `/api/tasks?title=a%00b` was 500.
  - With a genuine cursor, a NUL filter is `nul_character`, not `bad_cursor`. Failed first:
    `bad_cursor`.
  - Better Auth: a sign-up and an `update-user` with a NUL name, and a query with one, are 400
    `nul_character`; the name is unchanged. Failed first: `update-user` was 500.
  - "a tampered keyset cursor": a far-off time (`99999`, `-100000-…`), a NUL id and a 129-character
    id on the inbox, comments and agent runs are 400 (`bad_cursor` for all but the long id, which
    the schema refuses first). Failed first: 500.
  - The tampered entity-list cursor loop gains a NUL in a sort value and in the id: 400
    `bad_cursor` from the class-22 backstop (a missing test; it passed).
  - The routes fuzz gains `q`, `kind`, `status`, `id`, `entity` with a NUL and four tampered keyset
    cursors on every route. Failed first with 14 answers of 500 (comments, inbox, agent runs,
    mentionable, parties, jobs, acceptances, shares, documents, platform tenants).
- `sla.e2e.test.ts`: a cursor whose id holds a NUL is 400. Failed first (200 when run alone).
- `imports.e2e.test.ts`: a JSON import keyed by `constructor` reports the row without it as
  `missing_key`. Failed first: both rows created.
- `references.e2e.test.ts` (the fixture's new plans, form and undo window):
  - A revision naming an unknown room, another business's or one staff cannot read is refused
    alike, and makes nothing; one keeping its room, or naming it again, copies it. Failed first:
    the unknown room answered the database key's 404 without the field; the other two were 200.
  - A public form's answer naming any room is the reference's 404; naming none, 403
    `guest_cannot_wait`; no use spent, no customer made. Failed first: 403 `guest_cannot_wait`.
  - Undoing a delete whose room staff no longer read, or whose room was deleted, is 404 and the
    booking stays gone; with the room still theirs, it comes back. Failed first: restored (200).
  - Undoing a change of room back to one staff no longer read is 404 (passed before: `repo.update`
    checked it; pinned so the two agree).
- `money.e2e.test.ts`: `assertConfig` in a child process with `Intl.supportedValuesOf` deleted, or
  answering `[]`, refuses to start. Failed first: it started. The fixture's priced basket save in
  `ABC` writes nothing (a missing test; it passed).
- `framework/i18n/src/money.test.ts`: `canListCurrencies` (a new export, so this is not the
  failing-first evidence; the child-process e2e above is) is false with no function, an empty
  list or a throw, and true on Node.
- `integrations.e2e.test.ts` (missing test): on an endpoint of its own, `before=99999`,
  `-100000-01-01T00:00:00Z` and `not-a-date` are 400 `before is not a time`, and a page's
  `nextBefore` pages back.
- `application/api/test/domain/orders.e2e.test.ts`: an order stored in `ABC` (by SQL) is refused
  in `authorize` for the owner (`"ABC" is not a currency`, not `subtotal: …` from `run`) and for
  the assistant (403, no approval), and can still be cancelled. Failed first: the owner's answer
  came from `run`, and the assistant's save parked (`needs_approval`).
- `application/api/test/domain/references.e2e.test.ts`:
  - A note's PATCH with another business's meeting or an unknown id is refused alike (missing
    test; passed).
  - A member of two businesses: in their own, Alice's meeting is 404 though they read it in
    Alice's; in Alice's, their own meeting is 404 (missing test; passed).
  - The hook adds `notes_meeting_fk` to `app.notes` though a constraint of that name exists on
    another table, and a second run changes nothing. Failed first with the name-only guard: no key.
- `pnpm db:migrate` on `app_v10` (which had run the old guard): exit 0, both keys unchanged.

## Suggestions that did not hold

- **V2 review: "the integrator must generate the application migration, or `db:migrate` fails on
  a fresh database".** Already done on `feat/platform-gaps`: `application/domain/drizzle/0009_v2.sql`
  adds `meetings_tenant_id_uq` and drops both plain keys (checked with `grep -l
  meetings_tenant_id_uq application/domain/drizzle/*.sql`), and `app_tpl` was built from it.
- **V2 review: "mention the repair in the release notes".** The repository has no release notes
  or changelog (`ls docs`, no `CHANGELOG*`). The repair stays documented in V2.md's assumptions;
  recorded under Assumptions above for whoever cuts a release.
- **V4 review: "switch the fixtures' claims and payments to `KnownCurrencyCode`".** The reviewer
  marked it not required: those fixture entities have no money trait and store minor units
  only, so no exponent is guessed. Left as they are (Sites table).
- **A plain CRUD write of an amount on a stored-`ABC` row parks before it fails** (the same
  defect as the order's save, if it held). It does not: the money plugin's `decide`
  (`framework/core/src/plugins/money.ts`) runs `resolveMoneyInput` at the CRUD decision, so the
  assistant's PATCH is refused 403 `money_invalid` before it can park. Only commands, which the
  plugin sees in `run` alone, need their own check; the sample's only command that writes
  amounts is `order.save` (checked by `grep -l currency application/domain/src/modules/*/server/*.ts`:
  the other order files read or format amounts; `order.revise` copies them raw).

## Deferred

- A deployment's own currency codes (`VED` and the fund codes are refused today): V4's deferred
  item, now in guide section 14.
- The millisecond paging gap of timestamp sorts (V1's observation): guide section 14 ("Paging
  within one millisecond"). Fixing it changes every list cursor's format.
- A webhook payload holding a NUL is refused, not cleaned: guide section 14.
- A boot or lint warning for a drizzle foreign key to a table with `tenant_id` whose field is not
  in `traits.references` (V2 review, "later"): guide section 14.
- The fixture's claims and payments keep `z.string().regex(/^[A-Z]{3}$/)` (V4 review: none
  required).
