# H6: guides catch up with B12 and the H1 to H5 fixes

## Summary

A documentation unit from the completeness and security review. The developer guide's section
14 ("Not ready yet") still listed things later units built, and the guides did not yet describe
everything the fix units H1 to H5 changed. H6 ran while they were built, and wrote each item once
its unit had merged into `feat/platform-gaps` (all five did):

- F6/B12: the unused-package row names only `@mastra/memory`; B12's persisted query cache uses the
  React Query persister.
- H1 (notifications): guide 5.8 says how deciders hear of a request (push, else WhatsApp where it
  can be decided there, else email, and always the in-app inbox) and who is outside the team; the
  write-steps table names the held sends and the stored events' relay; 8.1, `DOMAIN.md`,
  `CLAUDE.md`, the tutorial and `new-application.md` follow (notifications from stored events, words
  read as each recipient may, `queueNotification` in a command).
- H2 (settings writers): guide 7.7 says who changes the `memory` section and how. H2 had already
  written 5.8.1, 5.13, 5.18 and 5.20 and removed its rows.
- H3 (credits and MCP): `DOMAIN.md`'s credits line names guardrail tokens and the refusal of an
  agent's next call. H3 (merged with S4's `embedding_tokens`) had already written 7.6, 7.7 and 7.8
  and trimmed its rows.
- H4 (privacy): guide 5.27 lists what a person's copy holds of calendars, calls, acceptance and MCP
  grants, beside H4's erasure text; section 14 says stored webhook payloads are not in a copy.
- H5 (orders): `DOMAIN.md` names the orders' states, `accepted` and the `orders-supplier` connector
  included; section 14's signers row says an accepted order can be cancelled. H5 had already
  written 5.14, 5.25 and its `DOMAIN.md` paragraphs and removed its row.

No code changes.

## Assumptions to review

- **Order of fallbacks for approval requests.** The guides describe the order H1 ships (push,
  else WhatsApp, else email; the inbox always). Should a business be able to change it per level,
  rather than the application through `overrideNotification`?
- **Webhook payloads in a person's copy.** Should a data-principal export include the stored
  delivery bodies and inbound payloads that mention the person (decision 9)?
- **Tutorial scope.** The tutorial is outside the brief's file list but contradicted merged code;
  H6 corrected it. Should the tutorial be kept in step by each unit instead?
