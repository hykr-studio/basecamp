# V7: the assistant's words and channel rendering say what is true

## Summary

Five low-severity defects from the live validation of the platform gaps (`VALIDATION.md` row 10:
C2-2, C2-3, C7-2, C9-2, C7-1). None changes what a write does; each made the words a person reads
untrue or unhelpful.

- **The waiting line names who decides (C2-2, A7, A5 #25).** A parked request that someone else
  decides (a capability's holders, a named person, the business for a contact) told the requester
  "I've asked for your approval ... until you approve it", and on WhatsApp the same message then
  said the team was asked. The line is now built from the approval, not only its summary: the
  parked call carries the approval's own `canDecide`, and `parkedLine(approval, turn)` says "I've
  asked the team for approval: ..." when it is false. WhatsApp no longer appends a second team
  line. The app's thread line ("approved by you", "waiting for your approval") follows the same
  fact.
- **WhatsApp links the request itself (C2-3, A5 #25).** "Approve it in the app" links
  `/approvals/<id>` (the deep link the app routes), on the turn and in a continuation.
- **A WhatsApp list's body is its heading (C7-2).** The text present intent carries the view's
  heading (`props.title`, else the view's `labels.title` in the turn's language). Buttons and
  lists use it as their body; without one, the whole text (cut to WhatsApp's body limit), never
  its first line alone.
- **The scripted model never says "the API answered undefined" (C9-2, A11).** It knows which
  tools the turn offers: a script's call to a tool the turn does not offer (a switched-off
  feature) answers "I can't do that here." A tool error that is not an API outcome reads as a
  plain refusal, and the API-status phrase is in every language.
- **A masked push token tells devices apart (C7-1, A9).** One mask, used by the device list and
  the personal-data export, keeps the token's prefix and the first characters of its id.

## The class: every site that told the requester to approve

| Site | Before | Now |
|---|---|---|

| `framework/app/src/chat/ToolPart.tsx` (the thread's line for a parked call) | "approved by you", "waiting for your approval" | "approved", "waiting for the team" when `canDecide` is false |

| `framework/api/src/channels/whatsapp/inbound.processor.ts` (button answers) | `/approvals/<id>` without encoding | encoded, as everywhere else |

Checked and left: the decider's notification ("Waiting for your approval: …", `approval.request`)
goes to the decider, so "your" is right there; `approval.expired` for a button whose token is not
genuine links `/approvals` (no trusted id).

## Assumptions to review

- A team-decided request on WhatsApp gets no link to `/approvals/<id>`. A contact (the usual
  case) cannot open the business's app, so a link would point them nowhere; a staff member finds
  the request in the app's waiting list. Listed in Deferred.
- A Hindi or Telugu written app turn now says the long waiting line instead of "That needs your
  OK. I've put it on screen." The card still shows below it.
- `said.notAvailable` ("I can't do that here.") does not say why: a switched-off feature is the
  business's setup, and the framework does not name it.

## Test plan

- `framework/agents/src/durable.test.ts` (a real Mastra agent on the scripted model): a suspended
  call with `canDecide: false` ends the reply with the team line (en, hi, spoken with and without
  a screen); one without `canDecide` keeps the old line; an agent that does not offer the tool a
  script calls answers "I can't do that here." and never reaches the API.
- `framework/agents/src/fake/engine.test.ts`: a script's call to a tool the turn does not offer
  answers "I can't do that here."; an `error-text` or `error-json` output never says "undefined";
  a Hindi refusal's status reason is Hindi.
- `framework/channels/src/channels.test.ts`: the approve-in-the-app link is
  `http://app/approvals/ap1`; a list or buttons without a heading carry the whole text, with one
  the heading.
- `framework/api/test/framework/wa-approvals.e2e.test.ts`: a customer's request says the team
  was asked, once, never "your approval"; the owner's own still says "your approval"; the tasks
  the delete looked through go as buttons or a list headed "Tasks" (the fixture view's
  `labels.title`; its text has no heading line), which covers `inWords` to `render` end to end.
- `framework/api/test/framework/settings.e2e.test.ts`: with the flag off, "polish gadget" answers
  "I can't do that here." with no tool call (a fixture script that calls the tool unconditionally);
  with it on, the same words call the tool and it parks (the offered names are the tools' ids).
- `framework/api/test/framework/push.e2e.test.ts`: two Expo tokens list with distinct masks; the
  export uses the same mask.
- `application/api/test/domain/todo-settings.e2e.test.ts`: the flag-off reply is "I can't do that
  here."
- Every existing own-request assertion (resume, comments, jobs, calendar, order-document,
  durable.test) stays byte-identical.
